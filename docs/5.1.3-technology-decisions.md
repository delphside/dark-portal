# Technology decisions

The technologies Dark Portal is built with, each with the line of reason that
chose it. The arguments are in the issues named.

> **Draft for #7's design.**

| Area | Choice | Why |
| --- | --- | --- |
| language | Rust for `dp`, built for `aarch64` and `x86_64` | one small binary with typed errors, the same language as Tile Lite Elite (#4) |
| logic | DuckDB SQL: views, macros and migrations, shipped in the image | transform once, and read by every client alike (#4) |
| DuckDB in Rust | embedded, through the `duckdb` crate, with its extensions installed into the image at build | each hour commits as one transaction, errors come back typed and nothing downloads at run time |
| bronze | plain Parquet: snapshots parsed into columns, item responses kept as JSON | readable by anything, and survives the loss of the catalog (#5); a year fits the bucket's free 20 GB |
| meta, silver, gold and reference | DuckLake tables over Parquet, with a SQLite catalog | an hour commits or rolls back as one, and past states can be queried (#5) |
| time arithmetic | `dp`'s SQL uses no ICU function: an hour is compared by its number, from `epoch_ms`, and the image installs only the `ducklake` and `sqlite` extensions | the bundled DuckDB has no ICU, so `epoch`, `date_diff` and arithmetic on a `TIMESTAMPTZ` are not there |
| HTTP | the `ureq` crate, blocking, with `rustls` | no system OpenSSL to match on the host, and no async runtime for a job that makes one request at a time |
| JSON | `serde_json`, parsing each snapshot as a stream | memory stays flat however large the snapshot |
| scheduling | a systemd timer per job, and a VM-wide lock file | the host's own scheduler, and jobs that never overlap (#11) |
| packaging | one container image per release, configured by its environment's `.env` | the same image in every environment (#11) |
| clients | a Python notebook on the owner's machine first, then a CLI command in `dp` | lookups and analysis are different jobs (#3) |
| the clients' copy | an export of plain Parquet with the views' SQL, pulled by rsync | readable without DuckLake, by the notebook and later Mathematica |
