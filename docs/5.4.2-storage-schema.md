# Storage schema

Every file and table Dark Portal keeps, and its columns. Each column's type and
meaning is in [5.4.5](5.4.5-data-dictionary.md); the layers are explained in
[5.1.1](5.1.1-architecture.md#data-layers).

> **Draft for #7's design.** Stage 1's tables only.

## Bronze: Parquet files

| File | Columns |
| --- | --- |
| `bronze/commodities/eu/YYYY-MM-DDTHH.parquet` | `hour`, `last_modified`, `fetched_at`, `id`, `item`, `quantity`, `unit_price`, `time_left` |
| `bronze/items/YYYY-MM-DDTHHMMSS.parquet` | `item`, `fetched_at`, `body` |

## The lake: DuckLake tables

One DuckLake catalog per environment, a SQLite file beside its Parquet data.

### meta

| Table | Key | Columns | Kept |
| --- | --- | --- | --- |
| `processed` | `market`, `hour` | `bronze_file`, `span`, `committed_at` | always |
| `gap` | `market`, `hour` | `found_at` | always |

`processed`'s latest hour is the high-water mark: the transform takes every
bronze hour after it, in order.

### silver

| Table | Key | Columns | Kept |
| --- | --- | --- | --- |
| `live_listing` | `id` | `item`, `unit_price`, `quantity`, `time_left`, `first_seen`, `last_seen`, `posted`, the queue at posting: `posting_lowest`, `posting_position`, `posting_units_ahead`, `posting_units_at_or_below` | while live |
| `listing_hour` | `id`, `hour` | `quantity`, `time_left`, `position`, `units_ahead` | while live |
| `event` | `hour`, `id`, `kind` | `item`, `units`, `unit_price`, `tier`, `rule`, `span` | no retention yet |
| `listing_record` | `id` | the columns of `ListingRecord` in [5.2.2](5.2.2-listing-lifecycle-and-events.md#the-key-types), the queue places flattened as `posting_*` and `end_*` | no retention yet |

A listing in the first snapshot collected, or first seen after a gap, has no
`posted` and no queue at posting.

### gold

| Table | Key | Columns | Kept |
| --- | --- | --- | --- |
| `price_level_hour` | `item`, `hour`, `unit_price` | `units`, `listings` | 4 weeks |
| `item_hour` | `item`, `hour` | `lowest`, `units_listed`, `listings`, `posted_units`, `sold_floor_units`, `sold_estimate_units`, `expired_units`, `cancelled_units`, `span` | 4 weeks |
| `item_day` | `item`, `day` | `lowest`, `median_fill_price`, `default_n`, `posted_units`, `sold_floor_units`, `sold_estimate_units`, `hours_held` | indefinitely |

`price_level_hour` holds every price level of every item each hour, so the
depth ladder and the fill price for any *N* can be read for any hour in the
last 4 weeks.

### reference

| Table | Key | Columns |
| --- | --- | --- |
| `item` | `item` | `name`, `class`, `subclass`, `vendor_sell_price`, `vendor_buy_price`, `fetched_at` |

`item` is rebuilt from bronze's item files: the latest record for each item
wins.

## Views and macros

The measures of [5.2.3](5.2.3-consumable-profiles.md) are views and macros over
these tables, so every client reads the same numbers.

| Name | Gives |
| --- | --- |
| `fill_price(item, hour, n)` | the average unit price of the cheapest *n* units in that hour, and the units it covers |
| `default_n(item, hour)` | the median hourly `sold_estimate_units` over the 7 days before the hour, rounded up, at least 1 |
| `depth_ladder(item, hour)` | each price level with its units, the units at or below it, and the hours they last |
| `profile` | for each item at the latest hour: the reference columns, `lowest`, the fill price at the default *N*, and the last 24 hours' flows |

## Expiry

Rows past their keep time are deleted daily, and DuckLake's snapshot expiry
and file clean-up then remove their files. Bronze on the host is deleted after
the days in [5.4.1](5.4.1-configuration.md), once the bucket holds it.
