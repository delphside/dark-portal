# Configuration

Every setting Dark Portal has. A *keep* deletes what is older than it, by the
hour or day a row or file is for. Deployment settings are environment
variables in each environment's `.env`; product settings are constants in one
code module per area
([1.10](https://github.com/delphside/programme/blob/main/docs/1.10-development-standards.md#where-an-applications-settings-are-held)).

> **Draft for #7's design.** Measured sources are in the capacity plan
> [`DP_CP_2026_10`](https://github.com/delphside/programme/blob/main/applications/dark-portal/3.2.3-capacity-plan/DP_CP_2026_10.md);
> the rest are reviewed once collection runs.

## Deployment settings

| Variable | Holds |
| --- | --- |
| `DP_ENV` | the environment's name, from the list in #11 |
| `DP_DATA_DIR` | the environment's data folder, `/srv/dp/<env>` (#11) |
| `DP_BLIZZARD_CLIENT_ID` | the Blizzard client's ID |
| `DP_BLIZZARD_CLIENT_SECRET_FILE` | a file holding the client's secret, readable by the environment's user only; the secret is never logged, nor written to bronze or the export |
| `DP_BUCKET` | the Object Storage bucket bronze and the daily history are pushed to, or empty for none |
| `DP_BUCKET_ACCESS_FILE` | a file holding what gives `dp` write access to the bucket, readable by the environment's user only; required where `DP_BUCKET` is set, and read only then. The address of a pre-authenticated request for the bucket ([5.1.3](5.1.3-technology-decisions.md)), which is a secret: never logged, nor written to bronze or the export |
| `DP_LOCK_FILE` | the VM-wide lock every writing job takes: `/srv/dp/dp.lock` |
| `DP_ADHOC_MEMORY_LIMIT` | DuckDB's `memory_limit` for an ad hoc query: 4 GB in production, 8 GB outside it |
| `DP_ADHOC_THREADS` | DuckDB's `threads` for an ad hoc query: 1 |
| `DP_CONTAINER_MEMORY` | the container's memory limit: the ad hoc limit plus 1 GB, so 5 GB in production and 9 GB outside it |
| `DP_IMAGE`, `DP_RUN_USER` | read by the units' script, not by `dp` ([5.3.2](5.3.2-operating.md#the-env)): the release's image, and the user the container runs as |
